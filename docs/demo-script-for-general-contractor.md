# ゼネコン向けデモスクリプト - MC-Gate 顔認証システム

## デモ概要

**対象**: ゼネコン担当者（現場管理者、安全管理者）
**所要時間**: 約15分
**目的**: MC-Gateの顔認証機能とルールベース入退場管理の実力を見せる

---

## 事前準備

### 環境
- **Face API サーバー**: 起動済み (http://192.168.1.4:8101)
- **モバイルアプリ**: 最新版インストール済み
- **テストデータ**: E2E_ALLOW, E2E_WARN, E2E_BLOCK の3名登録済み

### デモ端末
- スマートフォン or タブレット（Android/iOS）
- 大型ディスプレイまたはプロジェクターに画面ミラーリング推奨

### プロジェクト設定
- 「CCUS技能者ID確認」: ON
- 「社会保険確認」: ON

### セリフ例

>

> 2. **CCUS登録・社会保険加入状況を自動チェック**

### 見せるもの
- アプリのホーム画面
- タブ構成（認証、顔登録、履歴、設定）

## シーン2: 現場ルール設定（2分）

### セリフ例

> 「まず、現場ごとのルール設定を行います。」
>
> 「例えば、この現場では：
> - CCUS技能者ID登録が必須
> - 社会保険加入が必須
> という厳格なルールを適用します。」

### 操作手順
1. **設定タブ**を開く
2. 「プロジェクト設定」セクションを表示
3. 「CCUS技能者ID確認」を **ON** にする
4. 「社会保険確認」を **ON** にする

### セリフ例（続き）

> 「これで、ルールに違反する作業員は自動的に入場拒否されます。」
>
> 「ルールは管理者がいつでも変更できます。」

---

## シーン3: 作業員の顔登録（2分）

### セリフ例

> 「次に、作業員の顔を登録します。」
>
> 「登録は1人あたり**約5秒**で完了します。」

### 操作手順
1. **顔登録タブ**を開く
2. カメラに自分の顔を向ける
3. Person IDで「E2E_ALLOW（E2E太郎）」を選択
4. 「登録」ボタンをタップ

### セリフ例（続き）

> 「登録完了です。これでE2E太郎さんは顔だけで入場できるようになりました。」
>
> 「登録した顔は、サーバーに暗号化されて保存されます。」

## シーン4: 通常入場（ALLOWパターン、3分）

### セリフ例

> 「それでは、実際に入場してみます。」
>
> 「E2E太郎さんは、CCUS登録済み・社会保険加入済みなので、**問題なく入場できるはず**です。」

### 操作手順
1. **認証タブ**を開く
2. カメラに自分の顔を向ける
3. 顔検出 → 認証中... → 結果表示

### 見せるポイント

#### UI表示
- Alert（またはカード）に「入場登録完了」
- 氏名、会社名、認証方法、CCUS ID が表示される
- 「✅ 問題なく登録されました」のメッセージ

#### セリフ例（結果表示後）

> 「はい、**入場登録完了**です。」
>
> 「裏では以下のことが自動で行われています：
> 1. **顔認証による本人確認**（約1秒）
> 2. **CCUS登録・社会保険加入のチェック**
> 3. **入場履歴のローカルDB保存**
> 4. **オンライン時にサーバーへ自動同期**」
>
> 「作業員は**顔を向けるだけ**で、これらすべてが完了します。」

### オプション: adbログ確認（技術者向けデモの場合）

```bash
adb logcat *:S ReactNativeJS:V | grep -E "\[Auth\]|Active checkConfig"
```

> 「開発者向けには、こちらのログで設定とルール判定の詳細が確認できます。」

- 氏名、会社名、認証方法、CCUS ID

#### セリフ例（結果表示後）

>
> 「このように、入場は許可するが**管理者には注意喚起**する、という柔軟な運用ができます。」

> 「履歴データには『warn』として記録されるので、後から統計分析も可能です。」

1. **認証タブ**で E2E_BLOCK の顔で認証

## 技術補足（技術者向けデモの場合）

### アーキテクチャ
- **モバイルアプリ**: React Native + Expo
- **顔認証エンジン**: face-api.js (サーバーサイド)
- **ローカルDB**: SQLite (expo-sqlite)
- **サーバーDB**: PostgreSQL
- **オフライン同期**: OfflineQueue + SyncWorker

### セキュリティ
- OAuth 2.0 / Keycloak による認証・認可
- HTTPS通信（本番環境）
- 顔エンベディングの暗号化保存
- 冪等性キーによる重複送信防止

### スケーラビリティ
- 1現場あたり数百名〜数千名の作業員に対応可能
- 複数の現場で並行運用可能
- 将来的にはリアルタイムデジタルサイネージ機能も実装予定
